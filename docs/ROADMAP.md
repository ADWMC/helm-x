# helm-x-wails 路线图

> 里程碑、范围边界、迁移路径。本文回答"做到什么算做完"与"什么不做"。

---

## 1. 项目定位（一句话）

用 Go + Wails v3 + Vue 3 重写 `helm-x`，**修掉旧版的结构性缺陷**，而不是换个语言把同样的房间重盖一遍。

判据不是"功能对得上"，而是：

1. `PLAN.md` §1 的十条不变量逐条有断言
2. 60 题矩阵通过率 **≥ 93.9%**（旧版水平）
3. UI 的六项视觉缺陷（`DESIGN.md` §0-A）逐项消除

---

| M | 名称 | 内容 | 出口条件 |

## 3. 范围边界

### 3.1 做

| 类别 | 项 |
|---|---|
| 代理核心 | 注入、TAMPER、cyber → 改写 → clean session、上游重试 |
| 配置 | `config.toml` 注入/备份/还原（原子、可回滚） |
| 运维 | 自检、e2e 激活、自愈守护、日志 |
| 界面 | 10 页桌面窗口、事件推送、托盘、单实例 |
| 分发 | 单 exe、资源加密、CLI 兼容 |

### 3.2 不做（明确排除）

| 项 | 理由 |
|---|---|
| 非 Windows 平台 | 用户群单一；代码不写 `windows/*` 专有 API 即可留余地 |
| 数据库 | 配置量小，JSON 够用；引入 DB 是无理由的复杂度 |
| 多用户 / 权限系统 | 单机本地工具 |
| 主题选择器 | 跟随系统即可（`DESIGN.md` §5.3） |
| 图表库 | 请求量趋势自绘 SVG；不为一个折线图拖进 ECharts |
| 插件系统 | 没有第三方扩展需求 |
| 自动更新 | 有 QA 云更新已够；自更新引入签名与回滚复杂度 |
| **Context Gardener** | **实测功能空转**（裁剪目标 type 已不存在），用户决策删除。旧配置字段读取时忽略、不写回 |
| 移动端 / 响应式到手机 | 最高优先级是桌面窗口；960/680 断点只是防畸形缩放的底线 |

### 3.3 待定（需用户决策后才进入范围）

| 项 | 影响 | 对应问题 |
|---|---|---|
| 界面文案语言 | 中文 / 中英双语 → 术语表要单列还是双列 | `PLAN.md` §9.8 |
| 版本号方案 | `v0.1.0` 接续 vs `v2.0.0` 标明重写 | `PLAN.md` §9.4 |
| 提示词变体保留范围 | 5 个变体全留 vs 只留在用的 | `PLAN.md` §9.6 |
| 本地改写规则 | 默认 `none` vs 保留为 fallback | `PLAN.md` §9.2 |

## 4. 迁移路径

### 4.1 用户侧：零迁移

| 旧版资产 | 新版 |
|---|---|
| `%APPDATA%\helmx.config.json` | **字段一一对应，直接可用**。新增字段用 `omitempty`，旧版读到会忽略 |
| `~/.codex/config.toml` | 不变。新版注入方式与旧版一致 |
| CLI 用法 | 全部保留（`PLAN.md` §5.5） |
| 提示词 / TAMPER 规则 | 内容不变，只换加载方式 |

### 4.2 回滚路径

用户从新版退回旧版：

```
1. helmx remove           # 还原 config.toml，清理注入
2. 换回旧版 exe
3. 旧版读同一个 helmx.config.json —— 兼容
```

**不做自动迁移**，因为不需要：字段一一对应，没有格式变更。

### 4.3 双版本共存

发布初期允许并行：

- 新版默认监听 `1800`（与旧版一致，二者不能同时运行）
- 提供 `--listen 1801` 供 A/B 对照
- **同一时间只允许一个版本注入 `config.toml`** —— 通过备份文件的存在性检测并在 GUI 提示

## 5. 与旧仓库的关系

| 项 | 处理 |
|---|---|
| 旧仓库 | 保持可构建、可发布，作为对照基线 |
| 新仓库 | 独立演进 |
| `assets/` | 复用内容，不复制构建产物（`resources_generated.cpp` 不带过来） |
| `tests/*.py` | 60 题矩阵脚本复用（改指向新代理）；其余 Python 测试用 Go 重写 |
| 文档 | README / CHANGELOG 新版重写；本套 docs 为新版权威 |

## 7. 建议的下一步

按 `PHASES.md` 的依赖顺序，**阶段 A** 是唯一无阻塞且能立即降低最大风险的动作：

- 不需要上游 relay、不需要 codex、不需要 API key
- 用假上游 + 临时 `CODEX_HOME` 即可完成
- 结论直接决定 `PLAN.md` §5.5 状态机是否值得写

**在阶段 A 出结论前，不建议投入阶段 1 的编码。**
