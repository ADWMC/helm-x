## 2. 技术风险

### R-2 保序 JSON 扫描器移植出错

| 项 | 内容 |
|---|---|
| **触发** | 边界处理错误（代理对、转义、重复 key、大整数） |
| **影响** | 请求体被改坏 → codex 直接报错 → 会话中断（违反 INV-1） |
| **早期信号** | 保真测试失败：改一个字段后其余字节不再相同 |
| **缓解** | 用真实 codex 请求体做 fixture；`go test -fuzz` 跑 30s |
| **兜底** | 任何 `Parse` 失败一律**原样透传**（INV-9），不猜、不部分改写 |

### R-3 首段缓冲窗口参数选错

| 项 | 内容 |
|---|---|
| **触发** | 窗口太小 → 短拒绝流漏过补救；太大 → 首字延迟变差 |
| **影响** | 要么补救失效，要么流式体验退化回旧版水平 |
| **早期信号** | 请求页里 `action=pass_through` 占比异常高，或首字节延迟分布右移 |
| **缓解** | 参数可配（`stream_window_bytes` / `stream_window_ms`）；请求页可视化实际触发率 |
| **兜底** | 提供 `--passthrough` 直通模式做对照；默认值保守（2048B / 400ms） |

### R-4 Wails v3 beta API 变动

| 项 | 内容 |
|---|---|
| **触发** | 升级 beta 版本时 `application.Options` 等签名变化 |
| **影响** | 编译失败，但不影响核心逻辑 |
| **早期信号** | 升级后 `internal/svc` 或 `main.go` 编译错误 |
| **缓解** | Wails 调用**只出现在 `internal/svc/` 与 `main.go` 两处**；领域层零 Wails 依赖 |
| **兜底** | 锁定 `v3.0.0-beta.26`，升级前先跑通验收 |

### R-5 上游 API 形态变化

| 项 | 内容 |
|---|---|
| **触发** | 上游从 Responses API 换成 chat_completions 或其他 |
| **影响** | 注入与字段手术全部失效 |
| **早期信号** | `Classify` 大量返回 `Malformed` |
| **缓解** | `Adapter` 接口隔离协议；未知形态透传 |
| **兜底** | 新增一个 `Adapter` 实现即可，不动管线 |

### R-6 WebView2 运行时缺失

| 项 | 内容 |
|---|---|
| **触发** | 老系统无 WebView2 |
| **影响** | GUI 起不来 |
| **早期信号** | 启动报错 |
| **缓解** | Wails 自带 bootstrapper 引导安装 |
| **兜底** | 自动降级到 `helmx ui`（浏览器控制台）或 `helmx proxy` 无头模式 |

### R-7 进程退出时 config.toml 未还原

| 项 | 内容 |
|---|---|
| **触发** | 强杀进程、断电 |
| **影响** | 用户 codex 的 base_url 仍指向已关闭的本地代理 → codex 完全不可用 |
| **严重度** | **高** —— 这是最坏的失败模式，用户会以为工具搞坏了环境 |
| **缓解** | 三处兜底：信号处理、`OnShutdown`、代理循环退出后再次还原（旧版也是三重，`proxy.cpp:1412-1417`） |
| **兜底** | `helmx proxy --restore` 手动还原；启动时若检测到代理态残留则提示 |
| **验收** | 阶段 3 的 `TestByteRoundTrip` + 强杀冒烟测试 |

## 4. 供应链与合规

### R-11 凭据泄露

| 项 | 内容 |
|---|---|
| **现状** | 旧版 XOR 密钥 `0x5A5A` 硬编码在 `tools/embed.py`，源码注释自陈 "NOT cryptographic, just anti-glance" |
| **影响** | `assets/rewriter_builtin.json`（内置免费改写凭证，不在 git）实际处于零保护状态 |
| **缓解** | 密钥外部化：`HELMX_ASSET_KEY` 环境变量 → `%APPDATA%\helmx\asset.key`；算法换 `AES-GCM`；缺失时**构建失败**而非静默降级 |
| **兜底** | 开发用 `-tags plainembed` 显式走明文 |
| **诚实声明** | 这**不是安全边界**，本地工具防不住逆向。目标只是 `strings` 看不到、密钥不随仓库分发 |

### R-13 工具链版本陷阱（已踩）

| 陷阱 | 症状 | 处理 |
|---|---|---|
| `vitest@2` 自带一份 vite | `vue-tsc` 报 `Plugin<Api>` 类型不兼容 | 升 `vitest@^5` |
| `defineConfig` 从 `vite` 导入 | `test` 字段不被接受 | 从 `vitest/config` 导入 |
| `wrapper.attributes()` 用于多根组件 | 属性返回 `undefined`，误以为组件坏了 | 断言走 `wrapper.find()` |
| `--force-prefers-color-scheme` headless 无效 | 截图与深色**逐字节相同**（MD5 一致） | 显式加 `data-theme`；**比 hash 不比肉眼** |
